# 不同路径

## 问题

机器人位于 m × n 网格的左上角，m、n ≥ 1。每次只能向右或向下移动一格，求到达右下角的不同路径数。网格中没有障碍物。

对应 LeetCode 62。

## 思路

剩余的路径只取决于机器人所在的位置，而描述位置需要行和列两个独立的坐标：只记行号无法区分同一行的不同列，只记列号也一样。因此令 dp[i][j] 表示从 (0, 0) 到达格子 (i, j) 的路径数。这里需要二维，是因为状态本身需要两个信息，而不是因为输入看起来是一张网格。

到达 (i, j) 的最后一步只能来自上方 (i − 1, j) 或左方 (i, j − 1)。两类路径按最后一步区分，互斥且覆盖全部情况，所以 dp[i][j] = dp[i − 1][j] + dp[i][j − 1]。首行与首列只能一路向右或一路向下，路径数都是 1，这是缺少某个前驱时单独给出的最小子问题。

逐行计算时，每行只依赖上一行和同一行左侧刚算出的值，所以只需保存一行 R。新行 R′ 满足 R′[0] = 1 = R[0]，且 R′[j] = R′[j − 1] + R[j]。这恰好是 R 的前缀和，所以每处理一行，就把当前行替换为它的前缀和。

把网格转置后，路径与路径一一对应，答案不变。因此可以让较短的一维作为行长，另一维决定做多少次前缀和，额外空间只需 O(min(m, n))。

## 伪代码

```text
UNIQUE-PATHS(m, n)
    s ← MIN(m, n); l ← MAX(m, n)
    R ← [1 : j ∈ [0:s)]
    for i ← 1 to l − 1
        R ← PREFIX-SUMS(R)
    return R[s − 1]

PREFIX-SUMS(R)
    S ← COPY(R)
    for j ← 1 to |S| − 1
        S[j] ← S[j − 1] + S[j]
    return S
```

## 示例

3 × 4 网格的完整 dp 表：

| i \ j | 0   | 1   | 2   | 3   |
| ----- | --- | --- | --- | --- |
| 0     | 1   | 1   | 1   | 1   |
| 1     | 1   | 2   | 3   | 4   |
| 2     | 1   | 3   | 6   | 10  |

实现以较短的 3 为行长，对转置后的网格逐行取前缀和：`[1, 1, 1]` → `[1, 2, 3]` → `[1, 3, 6]` → `[1, 4, 10]`。得到的各行就是上表的各列，答案为 10。

## 正确性

不变量：第 i 次前缀和之后，R[j] = dp[i][j]，这里 dp 指转置后 l × s 网格中的路径数。

第 0 行全为 1，不变量成立。设处理前 R[j] = dp[i − 1][j]。前缀和保持 R′[0] = 1 = dp[i][0]；对 j ≥ 1，有 R′[j] = R′[j − 1] + R[j] = dp[i][j − 1] + dp[i − 1][j] = dp[i][j]。最后一行的末项即为右下角的路径数。

每条路径恰好包含 m − 1 次向下和 n − 1 次向右，由“在 m + n − 2 步中选出哪几步向下”唯一确定，所以答案也等于 C(m + n − 2, m − 1)。测试以此二项式系数作为独立的参考方法。

## 复杂度与实现

共做 l − 1 次前缀和，每次 s − 1 次加法，时间 Θ(mn)，额外空间 Θ(min(m, n))。

dp 沿行和列都单调不减，所以所有中间值都不超过最终答案。C++ 返回 `std::uint64_t`，只要求答案可表示，例如 m = n = 34 时答案 C(66, 33) ≈ 7.2 × 10¹⁸ 仍可表示。

Python 用 `functools.reduce` 折叠行数，每次由 `itertools.accumulate` 生成新行，峰值同时存在两行。C++ 用 `std::ranges::fold_left`，它会把累积值移入下一步，`std::inclusive_scan` 在原行上就地计算前缀和，不复制行。C++23 尚无前缀和视图，所以这里用 `<numeric>` 算法。Python 大整数加法的实际成本另计。
