# 规则正向推理

## 问题

给定有限事实集合 facts 和有序规则序列 rules。每条规则为 `(条件集合, 结论)`，表示所有条件同时成立时可推出结论。事实用字符串表示，规则只包含正事实，不含否定、撤销、变量替换或置信度。空条件表示无条件成立，允许重复规则与循环依赖。

按序扫描一轮规则，立即将每个新结论加入当前事实，以便本轮后续规则使用；一轮无新增事实时停止。返回 `Inference(facts, derived)`：最终事实集合，以及每个新事实首次推出的有序轨迹。原始事实不记入轨迹，每个新事实只记一次。

## 思路

把事实集想成一本只增不删的记录。每看一条规则，就检查它的条件是否都已记下：缺少条件就略过，结论已经知道也略过；否则把结论记入事实集，并追加到推导轨迹。

一次完整扫描称为一轮。上一条规则产生的事实立即交给下一条规则使用，这正是“左折叠”：按顺序把状态传下去。一轮结束后，只要增加过事实，就再检查一轮；直到状态不再变化，也就是到达不动点。

例如规则顺序为 `b → c`、`a → b`、`b → d`，初始只有 a。第一轮检查首条规则时还不知道 b，所以暂时跳过；第二条推出 b，第三条立刻利用 b 推出 d。第二轮才能由首条规则推出 c，第三轮无新增后结束。因此轨迹是 `(b, d, c)`，规则顺序会影响发现事实的先后。

## 伪代码

`FOLD` 从左到右应用转换，rules 在本次调用中保持只读。

```text
INFER(facts, rules)
    return CLOSE((COPY(facts), []))

APPLY((known, derived), (conditions, conclusion))
    if conclusion ∉ known and conditions ⊆ known
        return (known ∪ {conclusion}, derived ⧺ [conclusion])
    return (known, derived)

CLOSE(state)
    following ← FOLD(APPLY, state, rules)
    if |following.facts| = |state.facts|
        return following
    return CLOSE(following)
```

## 示例

初始事实 `{发烧, 咳嗽}`，规则为：

1. `{发烧, 咳嗽} → 可能流感`
2. `{可能流感} → 进行流感检测`
3. `{进行流感检测} → 等待检测结果`

第一轮得到三个新事实，第二轮无新增。最终集合包含两个原始事实和三个新事实。调用者可以逐步显示推导轨迹：

```python
from src.forward_chaining.solution import infer

result = infer(
    {"发烧", "咳嗽"},
    [
        ({"发烧", "咳嗽"}, "可能流感"),
        ({"可能流感"}, "进行流感检测"),
        ({"进行流感检测"}, "等待检测结果"),
    ],
)
for fact in result.derived:
    print(f"推出新事实：{fact}")
```

## 正确性

可靠性：初始事实已知，每次新增结论都有一条所有条件已知的规则支持，故轨迹中的每一步都是合法推导。

事实只增不减，因此比较一轮前后的事实数量即可判断是否达到不动点，无需比较完整集合或推导轨迹。

闭包性：最后一轮没有新事实，说明所有条件已满足的规则，其结论都已在集合中。继续用这些规则也无法增加事实，这样的集合称为对规则封闭。

最小性：任取包含初始事实且对规则封闭的集合 M。归纳可得每次新增事实都属于 M：规则条件已在 M 中，封闭性保证结论也在 M 中。因此结果包含于所有这样的 M，是最小闭包：恰好收集这些规则能够推出的事实，不额外猜测其他事实。

终止性：最多只能新增规则中出现的不同结论，每个有进展的轮次至少增加一个，故有限轮后停止。循环依赖不会导致无限推理；没有初始支撑的环也不会自行产生事实。规则顺序可能影响轨迹，但不影响最小闭包。

## 题目中的知识表示与推理类型

- facts 是命题式事实表示，用集合记录当前为真的原子命题；未出现表示尚未推出，不等同于显式否定。
- rules 是产生式规则表示，也可视为命题确定 Horn 规则：若若干原子命题的合取成立，则推出一个原子命题。
- 从已知事实不断触发规则属于正向推理，也称数据驱动推理。
- 在给定事实和规则成立的前提下推出结论，属于演绎推理；它不从样本学习新规则。

## 复杂度与实现

设初始事实数为 F，新增事实数为 D，P 为所有规则的条件数加规则数。最多扫描 D + 1 轮。以下先将字符串比较、哈希和集合元素视为单位成本，字符串实际长度另计。

成本分为两部分：反复检查规则，以及保存新事实。Python 用 `frozenset` 和元组保存不可变状态；哈希集合操作按平均成本计，一轮规则检查为 O(P)，每次新增还需复制事实集合和轨迹。总时间的保守上界为 O((D + 1)P + (D + 1)(F + D + 1))。递归会保留先前各轮的状态，额外空间上界为 O((D + 1)(F + D + 1))，包含最终结果。

C++ 用 `set` 管理事实，以 `fold_left` 和移动语义传递独占状态，在调用内原位插入新事实，返回集合和轨迹均拥有字符串。时间为 O(F + (D + 1)P log(F + D + 2))，额外空间 O(F + D + 1)，包含结果和递归栈。空规则直接结束。

规则和条件集合始终只读；规则序列必须可重复遍历，因为可能扫描多轮。

尾递归深度最多 D + 1；Python 不消除尾调用，C++ 也不保证尾调用优化。反向排列的长规则链可能触及递归上限或栈空间限制，不调整递归上限，也不保留跨调用缓存。
