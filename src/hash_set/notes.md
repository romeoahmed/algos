# 整数哈希集合

## 问题

不借助内建的哈希容器，实现一个整数集合：

- add(k)：插入 k，已存在则不变；
- remove(k)：删除 k，不存在则不变；
- contains(k)：判断 k 是否在集合中；
- 查询元素个数。

add 和 remove 返回集合是否发生了变化。课件介绍的两种冲突处理方法都要实现：链地址法与开放寻址法（线性探测）。

对应 LeetCode 705。

## 思路

直接寻址要按整个键空间分配数组，而 32 位整数就有 2³² 个可能的键。哈希表只分配与元素个数相当的 m 个桶，用哈希函数把键压缩成桶下标，再在这个候选位置比较真实的键。键比桶多，不同的键必然会落入同一个桶，这称为冲突；冲突无法消除，只能处理。

### 链地址法

每个桶挂一条链，保存所有落入该桶的键。查找、插入、删除都先定位桶，再沿链比较。插入前必须先查找，已存在就不插入，保证每个键至多出现一次；否则同一个键会留下多个节点，删除一次后仍能查到。

负载因子 α = n/m 就是平均链长。键数 n 一旦超过桶数 m，就把桶数翻倍并重新分配所有键，使 α ≤ 1。

### 开放寻址法

所有键直接存放在槽数组中，每个槽处于三种状态之一：EMPTY（从未使用）、占用（存放一个键）、DELETED（墓碑：曾经有键，后来被删除）。键 k 的探测序列为 (home(k) + i) mod m，i = 0, 1, 2, …。

- 查找沿序列前进：遇到 k 即找到；遇到 EMPTY 说明探测链到此为止，k 不存在；遇到 DELETED 不能停，后面可能还有经过这里才放下的键。
- 删除不能把槽改回 EMPTY，否则会截断经过它的探测链，后面的键将再也找不到；只能标记为 DELETED。
- 插入要先完整查找：记住途中遇到的第一个 DELETED，若直到 EMPTY 都没找到 k，就把 k 放进那个墓碑以复用空间，没有墓碑才放进 EMPTY。若在第一个墓碑处就停下插入，而 k 其实在更后面，集合里就会出现两个 k。

墓碑和真实的键一样会拉长探测，所以控制的不是 n/m，而是 (n + d)/m，d 为墓碑数。它超过 3/4 时重建：若 n 超过 m/2 就把容量翻倍，否则保持容量，只清除墓碑。

### 桶下标：Fibonacci 哈希

课件的基本公式是 index = hash(k) mod m。Python 的 `hash(int)` 和常见 C++ 标准库的 `std::hash<int>` 基本就是整数本身，m 又取 2 的幂，于是取模只保留键的低位：

- 低位相同的键全部冲突，例如 m = 64 时 0、64、128、… 都落入 0 号桶；
- 连续的键占据连续的槽。线性探测下，大量连续的键形成一整段没有空隙的占用区，查找落在这段中的不存在的键，要一路走到这段的末尾。测试插入四万个连续整数、删除其中一半后逐个查询，用取模时 Python 版本需要十几秒。

这正是课件强调“分布均匀”的原因。实现改用 Fibonacci 哈希（乘法哈希的一种）：设 m = 2ᵖ，

home(k) = ⌊(hash(k) · A mod 2⁶⁴) / 2⁶⁴⁻ᵖ⌋，A = 0x9E3779B97F4A7C15 ≈ 2⁶⁴/φ，

即乘以一个奇常数后取乘积的高 p 位。键的每一位都会影响乘积的高位，连续的键和低位相同的键因此被打散到整张表。同样的测试降到不足一秒。A 为奇数，乘法在模 2⁶⁴ 下可逆，不同的哈希值不会因乘法而合并。

## 伪代码

遵循[记号约定](../notation.md)。T.n 为键数，T.d 为墓碑数；`home(k)` 按当前的桶数或槽数计算。

```text
CHAINED-ADD(T, k)
    L ← T.buckets[home(k)]
    if k ∈ L
        return False
    APPEND(L, k)
    T.n ← T.n + 1
    if T.n > |T.buckets|
        REHASH(T, 2 · |T.buckets|)    // 按新桶数重新放置每个键
    return True

CHAINED-REMOVE(T, k)
    L ← T.buckets[home(k)]
    if k ∉ L
        return False
    从 L 中删去 k
    T.n ← T.n − 1
    return True

LOCATE(T, k)    // 返回 (k 所在的槽, True) 或 (k 应放入的槽, False)
    m ← |T.slots|
    free ← NIL
    i ← home(k)
    while T.slots[i] ≠ EMPTY
        if T.slots[i] = DELETED
            if free = NIL
                free ← i
        else if T.slots[i] = k
            return (i, True)
        i ← (i + 1) mod m
    if free = NIL
        free ← i
    return (free, False)

PROBING-ADD(T, k)
    (i, found) ← LOCATE(T, k)
    if found
        return False
    if T.slots[i] = DELETED
        T.d ← T.d − 1
    T.slots[i] ← k
    T.n ← T.n + 1
    m ← |T.slots|
    if 4(T.n + T.d) > 3m
        if 2 · T.n > m
            REBUILD(T, 2m)
        else
            REBUILD(T, m)    // 只清除墓碑
    return True

PROBING-REMOVE(T, k)
    (i, found) ← LOCATE(T, k)
    if not found
        return False
    T.slots[i] ← DELETED
    T.n ← T.n − 1
    T.d ← T.d + 1
    return True
```

contains 对链地址法是 k ∈ L，对开放寻址法是 LOCATE 返回的第二项。REBUILD(T, m′) 分配 m′ 个 EMPTY 槽，把每个键重新放到 LOCATE 给出的位置，墓碑数归零。

## 示例

为便于手算，本节沿用课件的 home(k) = k mod 8。实现中的桶下标不同，但每一步的判断完全相同。

依次插入 10、18、26、34，四个键的初始位置都是 2，沿探测序列落在 2、3、4、5 号槽。然后删除 18，再查找 26、插入 42：

| 槽     | 2   | 3       | 4   | 5   | 6     |
| ------ | --- | ------- | --- | --- | ----- |
| 删除前 | 10  | 18      | 26  | 34  | EMPTY |
| 删除后 | 10  | DELETED | 26  | 34  | EMPTY |
| 插入后 | 10  | 42      | 26  | 34  | EMPTY |

- 查找 26：2 号槽是 10，继续；3 号槽是墓碑，不能停；4 号槽找到。若删除时把 3 号槽改成 EMPTY，查找会在这里误判 26 不存在。
- 插入 42：初始位置 2。3 号槽是第一个墓碑，记为 free；继续比较 26、34，直到 6 号槽遇到 EMPTY，确认 42 不在表中，最后放入 3 号槽。

链地址法下，这些键都挂在 2 号桶的链上，删除 18 只需从链中摘下它。若继续插入，直到第 9 个键使 n > m，桶数就翻倍到 16，每个键按 k mod 16 重新分配：原来同在 2 号桶的 10、26、34、42 被分开，10、26、42 进入 10 号桶，34 留在 2 号桶。

## 正确性

链地址法的不变量：每个键 k 恰好出现在 home(k) 号桶的链中一次。查找只需检查这一条链。add 先查后插，保持唯一；remove 只改动这一条链；REHASH 按新的桶数重新放置每个键，不变量对新的 m 成立。

开放寻址法的不变量：对存放在 j 号槽的每个键 k，从 home(k) 沿探测序列走到 j，途中没有 EMPTY 槽。

- 插入：k 放在探测路径上第一个墓碑或第一个 EMPTY 处，此前经过的槽都不是 EMPTY，不变量成立。
- 删除：把槽改为 DELETED，不产生新的 EMPTY，其他键的路径不受影响。
- EMPTY 只在重建时出现，而重建会重新插入所有键。

因此 LOCATE 遇到 EMPTY 时可以断定 k 不在表中：若 k 在 j 号槽，从起点到 j 没有 EMPTY，查找会先到达 j。插入前的完整查找保证 k 不会因为复用墓碑而出现两次。

终止性：每次插入后都检查占用率，超过 3/4 立即重建，而重建后 (n + d)/m ≤ 1/2。翻倍时 n + d ≤ 3m/4 + 1，新容量下占用率约为 3/8；不翻倍时 n ≤ m/2 且墓碑清零。所以 LOCATE 运行时占用率至多为 3/4，至少有 m/4 个 EMPTY 槽，每条探测序列都会停下。

测试随机生成插入与删除序列，与标准库的集合（Python 的 `set`、C++ 的 `std::set`）逐步比对返回值、元素个数和成员关系，作为独立的参考方法。键混合了容易互相冲突的小整数、低位相同的 64 的倍数，以及任意整数。另外两项测试分别检查：同一个键反复插入、删除十万次后墓碑被清理，操作仍能结束；四万个连续整数插入后删除一半，查询结果正确且耗时正常。

## 复杂度与实现

在键均匀分布的假设下，链地址法每次操作期望 O(1 + α)，α ≤ 1。线性探测在占用率 α 下，失败查找的期望探测次数约为 (1 + 1/(1 − α)²)/2（Knuth），α ≤ 3/4 时不超过 8.5。因此两种方法的操作都是期望 O(1)；所有键都冲突时退化为 Θ(n)。

重建或重哈希一次 Θ(n + m)。每次之后，都要再插入与容量成正比的键才会触发下一次：链地址法约 m/2 个，开放寻址法至少 m/4 个。代价可以摊到这些插入上，所以插入是期望均摊 O(1)，与课件的“单次 O(n)、一系列插入均摊 O(1)”一致。两种实现都不收缩，空间为 Θ(历史最大 n)。

Python 中，链地址法的桶用列表代替链表，语义相同；开放寻址法的槽是整数或 `Mark` 枚举值，`Mark.EMPTY` 与 `Mark.DELETED` 分别表示空槽和墓碑。两个类都支持 `in` 和 `len()`。

C++ 中，链地址法的桶是 `std::forward_list<int>`，重哈希时用 `splice_after` 把节点直接移到新桶，不重新分配内存。开放寻址法的槽是带 `State` 枚举的结构体。两个类都是普通的值类型，复制集合会复制全部桶或槽。`std::hash<int>` 在 MSVC 上不是恒等函数，但乘法哈希对任何哈希值都适用。
