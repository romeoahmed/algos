# 0-1 背包

## 问题

给定若干物品，每件有非负重量 w 和非负价值 v；背包容量为非负整数 W。每件物品最多选一次，求总重量不超过 W 时的最大总价值。可以什么都不选，此时价值为 0。

## 思路

暴力做法给每件物品决定选或不选，共 2ⁿ 种方案。不同的选择顺序会走到相同的局面：已经考虑过同一批物品，剩下的容量也相同。动态规划要合并的正是这些重复局面，所以先确定一个局面需要哪些信息。

只记物品进度 i 不够：不知道还剩多少容量，就无法判断下一件能否放入。只记容量 j 也不够：不知道哪些物品已经考虑过，同一件物品可能被重复计入。两个坐标可以独立变化，缺一不可，因此令 dp[i][j] 表示只从前 i 件物品中选、总重量不超过 j 时的最大价值。

考虑第 i 件物品 (w, v) 的去留：

- 不选：问题退化为前 i − 1 件、容量仍为 j，即 dp[i − 1][j]；
- 选：先为它留出 w 的容量，再加上它的价值，即 dp[i − 1][j − w] + v，只在 w ≤ j 时合法。

dp[i][j] 取两者中较大的一个。这与[打家劫舍](../house_robber/notes.md)比较“选与不选”的方式相同，区别在于能否选由剩余容量决定，因此状态多了容量这一维。两个来源都在上一行，因为第 i 件物品在前 i − 1 件的子问题中还没有出现，这正是“每件最多选一次”在转移中的体现。边界是 dp[0][j] = 0：没有物品可选时价值为 0。初始行全为 0，所以 dp[i][j] 的含义是“不超过 j”，而不是“恰好为 j”，答案直接是 dp[n][W]。

每行只读上一行，可以只保存一行 B。原地更新时，B[j] 要读取的 B[j − w] 必须还是上一行的值。容量从大到小更新时，较小的下标还没被覆盖，条件成立；若从小到大更新，B[j − w] 可能已经计入当前物品，同一件物品就会被重复选择，算出的是每件可选任意次的完全背包。

## 伪代码

遵循[记号约定](../notation.md)。

```text
KNAPSACK(I, W)
    B ← [0 : j ∈ [0:W + 1)]
    for (w, v) in I
        for j ← W downto w
            B[j] ← MAX(B[j], B[j − w] + v)
    return B[W]
```

w > W 时内层循环不执行，物品放不进任何容量，这一行与上一行相同。

## 示例

W = 5，物品 A = (2, 3)、B = (3, 4)、C = (4, 5)：

| 已考虑 \ j | 0   | 1   | 2   | 3   | 4   | 5   |
| ---------- | --- | --- | --- | --- | --- | --- |
| 无         | 0   | 0   | 0   | 0   | 0   | 0   |
| A          | 0   | 0   | 3   | 3   | 3   | 3   |
| A, B       | 0   | 0   | 3   | 4   | 4   | 7   |
| A, B, C    | 0   | 0   | 3   | 4   | 5   | 7   |

例如加入 B 后，dp[2][5] = MAX(dp[1][5], dp[1][2] + 4) = MAX(3, 7) = 7，即同时选 A 和 B。加入 C 后，容量 5 时选 C 只能再配容量 1 的方案，价值 0 + 5 < 7，答案仍为 7。

更新顺序的差别可以用单件物品 (1, 1)、W = 4 观察。从大到小更新得到 `[0, 1, 1, 1, 1]`，答案 1；从小到大更新时，B[1] 刚变为 1，B[2] 就读到它，结果为 `[0, 1, 2, 3, 4]`，同一件物品被用了四次。

## 正确性

不变量：处理完前 i 件物品后，B[j] = dp[i][j]。

i = 0 时 B 全为 0，没有物品可选，成立。设处理第 i 件 (w, v) 前 B[j] = dp[i − 1][j]。前 i 件物品中、总重不超过 j 的任一方案，要么不含第 i 件，价值不超过 dp[i − 1][j]；要么含第 i 件，此时 w ≤ j，其余物品取自前 i − 1 件且总重不超过 j − w，价值不超过 dp[i − 1][j − w] + v。两种情况的最优方案都能取到，所以 dp[i][j] 就是两者中较大的一个。

内层循环从大到小更新。更新 B[j] 时，下标小于 j 的位置尚未改动，B[j − w] 仍是 dp[i − 1][j − w]；w = 0 时读写同一位置，读取发生在写入之前。下标小于 w 的位置不更新，保持 dp[i − 1][j]，与“放不下只能不选”一致。

测试枚举全部子集，取总重不超过容量者的最大价值，作为独立的参考方法。

## 复杂度与实现

共 n 行，每行 W + 1 个状态，每个状态 O(1)，时间 Θ(nW)，额外空间 Θ(W)。这里 W 是容量的数值而不是输入长度：W 写成二进制只需约 log W 位，所以 Θ(nW) 是伪多项式时间。一般的 0-1 背包是 NP 困难问题，容量很大时这张表并不实用。

只保存一行意味着无法回溯选了哪些物品；需要方案时应保留完整的 dp 表，从 dp[n][W] 倒推每件物品是否被选。

Python 用 `functools.reduce` 依次加入物品，会完整消耗迭代器。每一步由上一行直接构造新行：前 w 项照抄，其余由 `zip(best[w:], best)` 把 B[j] 与 B[j − w] 配对后取较大值。新旧两行同时存在，读取的总是上一行，因此不需要考虑更新顺序，峰值额外空间为两行。

C++ 用 `std::ranges::fold_left` 加入物品，累积的行被移入下一步，不复制。`std::views::zip` 把 `best | std::views::drop(w)` 与 `best` 配对，再经 `std::views::reverse` 从大到小原地更新，与伪代码一致。价值以 `std::int64_t` 累加，任意 `int` 价值在 n < 2³² 时都不会溢出。
