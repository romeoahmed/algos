# 两数之和

## 问题

给定整数序列 A 与目标值 t，找出两个下标 i < j，使 A[i] + A[j] = t。LeetCode 保证恰有一组解；这里不作此假设：返回扫描中最早完成配对的一组，即 j 最小的解，无解时返回 NIL。

对应 LeetCode 1。

## 思路

枚举所有下标对需要 Θ(n²) 时间。换个问法：扫描到 A[j] = x 时，与它配对的值已经确定为 t − x，问题变成“此前是否出现过 t − x，出现在哪个下标”，这是一次按键查找。于是用字典保存“已扫描的值 ↦ 下标”，每一步先查补数，再登记当前值。

**先查后存。** 若先登记 x 再查 t − x，当 x = t − x 时（如 t = 6，x = 3）会查到自己，把同一个元素用了两次。先查保证字典里只有严格位于 j 之前的元素。

**重复值。** 同一个值多次出现时，后出现的下标覆盖先出现的。任何一个都能与之后的元素配对，覆盖不影响能否找到解。

一对下标中较晚的那个总会在扫描到它时发现较早的那个，所以只需单向扫描一遍，不需要“回头”查找之后的元素。

## 伪代码

遵循[记号约定](../notation.md)。

```text
TWO-SUM(A, t)
    D ← 空字典    // 已扫描的值 ↦ 下标
    for j ← 0 to |A| − 1
        if t − A[j] ∈ D
            return (D[t − A[j]], j)
        D[A[j]] ← j
    return NIL
```

## 示例

A = `[2, 7, 11, 15]`，t = 9：

| j   | A[j] | 补数 | 查询前的 D | 结果        |
| --- | ---- | ---- | ---------- | ----------- |
| 0   | 2    | 7    | {}         | 登记 2 ↦ 0  |
| 1   | 7    | 2    | {2 ↦ 0}    | 返回 (0, 1) |

找到后立即返回，不再登记 7，也不再扫描后面的元素。

A = `[3, 3]`，t = 6：j = 0 时字典为空，先查不到 3，再登记 3 ↦ 0；j = 1 时查到 3 ↦ 0，返回 (0, 1)。若先存后查，j = 0 就会错误地返回 (0, 0)。

## 正确性

不变量：第 j 步开始时，D 的键恰为 A[0:j] 中出现过的值，D[v] 是 v 在 A[0:j] 中的某个下标。

- 若在第 j 步返回 (i, j)：i = D[t − A[j]] < j 且 A[i] = t − A[j]，是一组合法的解。
- 设 j* 是所有解中最小的第二个下标。j < j* 时不存在以 j 为第二个下标的解，D 中查不到补数，不会提前返回；第 j* 步时存在 i < j* 使 A[i] = t − A[j*]，由不变量这个值在 D 中，于是在第 j* 步返回。
- 无解时每一步都查不到补数，扫描结束后返回 NIL。

测试用双重循环枚举所有下标对作为独立的参考方法：检查返回的两数之和为 t、第一个下标小于第二个，且第二个下标是所有解中最小的；无解时两者都返回空。

## 复杂度与实现

单次扫描，每步一次查找、至多一次写入，期望时间 O(n)；所有值都冲突时最坏 Θ(n²)。额外空间 O(n)。

Python 接受 `Iterable[int]`，用 `enumerate` 单遍扫描，找到解就停止，迭代器只消耗到解的位置。返回 `tuple[int, int] | None`。

C++ 返回 `std::optional<std::pair<std::size_t, std::size_t>>`。补数 t − A[j] 可能超出 `int` 的范围，例如 t = −2³¹、A[j] = 1；若在 `int` 中计算会溢出，回绕后的值甚至可能恰好等于某个已扫描的元素，造成误报。所以补数和字典的键都用 `std::int64_t`。查询用 `find` 而不是 `operator[]`，避免课件提到的“查询时意外插入默认值”。
