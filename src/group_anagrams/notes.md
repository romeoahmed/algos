# 字母异位词分组

## 问题

给定字符串列表，把互为字母异位词的字符串分到同一组。两个字符串互为异位词，当且仅当一个能通过重排字符得到另一个，即每种字符出现的次数都相同。组按首次出现的顺序排列，组内保持输入顺序。

LeetCode 保证字符串只含小写字母 a–z，主函数沿用这一前提；另有一个版本适用于任意字符，用来比较课件中的数组计数与哈希计数。

对应 LeetCode 49。

## 思路

“互为异位词”是等价关系，分组就是求等价类。逐对比较需要 Θ(n²) 次比较。改为给每个字符串计算一个**签名**，使签名相同当且仅当互为异位词，再用字典按签名分组：签名 ↦ 组。每个字符串只需计算一次签名，再做一次期望 O(1) 的查找。

签名有三种常见选择，设字符串长 k：

| 签名                  | 计算       | 签名大小       | 前提         |
| --------------------- | ---------- | -------------- | ------------ |
| 排序后的字符串        | Θ(k log k) | k              | 任意字符     |
| 数组计数：26 个计数   | Θ(k + 26)  | 26             | 只含小写字母 |
| 哈希计数：字符 ↦ 次数 | 期望 Θ(k)  | 不同字符的数目 | 任意字符     |

### 数组计数与哈希计数

数组计数就是直接寻址：字符本身决定下标，没有哈希函数，也没有冲突，计数位于连续内存。代价是字符集必须事先已知、小而连续；签名固定为 26 个数，短字符串也要付出这部分开销。

哈希计数不限制字符集，签名只包含实际出现的字符。但每个字符串都要建立一张小哈希表，有分配、哈希和冲突处理的开销。

签名还要作为外层字典的键，因此自身必须可哈希，并满足课件强调的“相等的键哈希值相同”：

- 数组签名中，位置代表字母，按顺序组合各位置的哈希即可；
- 哈希表的遍历顺序没有保证，两张相等的计数表可能以不同顺序给出各项，所以组合方式必须与顺序无关。Python 用 `frozenset` 保存 (字符, 次数)；C++ 对每一项分别哈希，再求和。

在一台 Apple Silicon 机器上的一次测量：随机小写单词，CPython 3.14 每组 2 万个，C++（Clang，`-O2`）每组 20 万个，取五次中的最短时间，单位为毫秒。数值随机器而变，这里只看相对大小：

| 单词长度 | Python 数组 | Python 哈希 | Python 排序 | C++ 数组 | C++ 哈希 | C++ 排序 |
| -------- | ----------- | ----------- | ----------- | -------- | -------- | -------- |
| 5        | 6           | 13          | 4           | 36       | 54       | 14       |
| 20       | 12          | 25          | 11          | 40       | 141      | 34       |
| 100      | 43          | 58          | 75          | 51       | 255      | 190      |

- 数组计数始终快于哈希计数，C++ 中单词较长时相差约 5 倍：小哈希表的节点分配远比递增数组元素昂贵。
- 短单词时排序反而最快：数组计数的固定成本（26 个计数的初始化、哈希与比较）超过了 k log k。单词变长后，Θ(k) 的数组计数才显出优势。
- Python 中解释器开销压缩了差距：`sorted` 和 `Counter` 的循环在 C 中执行，数组计数的循环却逐字符解释执行。

结论与课件一致：字符集小而已知时，用数组计数；字符集大或未知（如任意 Unicode）时，用哈希计数。渐近复杂度只是一方面，常数、内存分配和数据规模同样决定实际表现。

## 伪代码

遵循[记号约定](../notation.md)。

```text
GROUP-ANAGRAMS(W, SIGNATURE)
    D ← 空字典    // 签名 ↦ 组在 G 中的下标
    G ← []
    for w in W
        s ← SIGNATURE(w)
        if s ∉ D
            D[s] ← |G|
            APPEND(G, [])
        APPEND(G[D[s]], w)
    return G

ARRAY-SIGNATURE(w)
    C ← [0 : i ∈ [0:26)]
    for c in w
        C[c − 'a'] ← C[c − 'a'] + 1
    return C

HASH-SIGNATURE(w)
    C ← 空字典    // 字符 ↦ 次数，缺省为 0
    for c in w
        C[c] ← C[c] + 1
    return C
```

## 示例

W = `["eat", "tea", "tan", "ate", "nat", "bat"]`：

| 单词 | 计数（只列非零项） | 动作        |
| ---- | ------------------ | ----------- |
| eat  | a1 e1 t1           | 新建第 0 组 |
| tea  | a1 e1 t1           | 加入第 0 组 |
| tan  | a1 n1 t1           | 新建第 1 组 |
| ate  | a1 e1 t1           | 加入第 0 组 |
| nat  | a1 n1 t1           | 加入第 1 组 |
| bat  | a1 b1 t1           | 新建第 2 组 |

结果为 `[["eat", "tea", "ate"], ["tan", "nat"], ["bat"]]`。`aab` 与 `abb` 字母种类相同但次数不同，签名不同，不是异位词。

## 正确性

签名相同 ⇔ 每种字符的出现次数相同 ⇔ 互为异位词。数组签名逐位记录 26 个字母的次数。哈希签名只记录出现过的字符，未出现的字符次数为 0，不在表中；两张表相等当且仅当它们含有相同的字符且对应次数相等，也就是所有字符的次数相同。

字典把签名映射到组的下标，所以签名相同的字符串进入同一组，签名不同的进入不同组。新签名第一次出现时在 G 末尾追加新组，组按首次出现的顺序排列；每个字符串按扫描顺序追加，组内保持输入顺序。

测试用排序作为独立的参考方法：顺序扫描，把每个字符串放入第一个“首元素排序后与它相同”的组，没有就新建一组。两种签名在小写输入上都与它比对；哈希签名另在任意字符（Python 含多字节 Unicode，C++ 含 NUL 和高位字节）上比对。

## 复杂度与实现

设共 n 个字符串，总长 L。数组计数期望时间 Θ(L + 26n)，哈希计数期望 Θ(L)；输出复制全部字符串，额外空间 Θ(L + 26n) 与 Θ(L)。

Python 的 `group_anagrams(words, signature=array_signature)` 以签名函数为参数，可换成 `hash_signature`。`array_signature` 返回 26 元组，`hash_signature` 返回 `frozenset(Counter(word).items())`，`frozenset` 的哈希本身与顺序无关。字典保持插入顺序，直接给出组的顺序。接受任意可迭代对象，迭代器会被完整消耗。

C++ 提供 `group_anagrams` 与 `group_anagrams_hashed` 两个函数，共用一个模板 `group_by`，签名分别是 `std::array<std::size_t, 26>` 与 `std::unordered_map<char, std::size_t>`。标准库没有为这两种类型提供 `std::hash`，所以像课件中的自定义键那样提供哈希函数对象：都用 SplitMix64 的混合函数打散每个数，数组签名按位置依次折叠，哈希计数签名把各项的哈希相加。`std::unordered_map` 的 `operator==` 与顺序无关，正好用作键的相等比较。外层字典映射到组的下标而不是直接保存组，以便按首次出现的顺序输出。哈希版本按字节计数：两个 UTF-8 字符串只要字节的多重集相同就会分到一组，即使它们的字符并不互为重排。
