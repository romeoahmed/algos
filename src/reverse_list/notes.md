# 反转链表

## 问题

给定单链表的头节点 head，反转链表并返回新的头节点；空链表返回 NIL。要求重连原有节点，不创建新节点。

对应 LeetCode 206。

## 思路

单链表只有指向后继的 next 指针，反转就是把每条边 a → b 改成 b → a。困难在于：一旦改写 cur.next，就失去了通往剩余链表的唯一路径。所以每一步都要先保存后继，再改指针。

把链表分成两段：已反转的部分，头为 prev；尚未处理的部分，头为 cur。每一步从未处理部分摘下首节点，接到已反转部分的头部。链表头部的插入和删除都是 O(1)，相当于把节点从一个栈逐个弹出、压入另一个栈，顺序自然颠倒。

整个过程只需要三个指针：prev、cur 和临时保存的 next。

## 伪代码

遵循[记号约定](../notation.md)。

```text
REVERSE-LIST(head)
    prev ← NIL
    cur ← head
    while cur ≠ NIL
        next ← cur.next    // 改写前先保存后继
        cur.next ← prev
        prev ← cur
        cur ← next
    return prev
```

## 示例

反转 1 → 2 → 3：

| 步骤 | 已反转（从 prev 起） | 未处理（从 cur 起） |
| ---- | -------------------- | ------------------- |
| 初始 | NIL                  | 1 → 2 → 3           |
| 1    | 1                    | 2 → 3               |
| 2    | 2 → 1                | 3                   |
| 3    | 3 → 2 → 1            | NIL                 |

每一步只改写一个节点的 next。原来的头节点 1 最终成为尾节点，指向 NIL。

## 正确性

设原链表为 a₀ → a₁ → … → aₙ₋₁。不变量：第 k 次循环开始时，prev 是 aₖ₋₁ → … → a₀ 的头（k = 0 时为 NIL），cur 是 aₖ → … → aₙ₋₁ 的头，两段不相交，合起来恰好包含全部节点。

一次循环先保存 aₖ₊₁，再让 aₖ 指向 aₖ₋₁，于是 aₖ 成为已反转部分的新头，cur 前进到 aₖ₊₁，不变量保持。循环在 k = n 时结束，此时 prev 是 aₙ₋₁ → … → a₀，即反转后的链表。每个节点恰好改写一次 next，没有节点丢失或重复。

也可以递归：先反转 head.next 之后的部分，再把 head 接到其尾部。时间同为 Θ(n)，但递归深度为 n，长链表会耗尽调用栈，因此这里用迭代。

测试先记录原链表的节点（Python 的对象身份、C++ 的地址）和值，反转后检查值序列与节点序列都恰为原序列的逆序，作为独立的参考方法。

## 复杂度与实现

每个节点处理一次，时间 Θ(n)，额外空间 O(1)。原链表被就地改写：调用后原头节点成为尾节点，调用者应改用返回值。

Python 的 `ListNode` 是带 `slots` 的数据类，关闭了自动生成的相等比较和表示：二者都会沿 next 递归，长链表会超出递归深度。`make_list` 借助哨兵节点从前向后建表，与课件中哨兵统一首元的做法相同。

C++ 用所有权表达链表：每个节点通过 `std::unique_ptr` 拥有后继，`List` 拥有从头开始的整条链。`reverse_list` 按值接收 `List`，即接管整条链，返回时再交出反转后的链，签名本身说明了输入会被改写。每一步只是三次指针移动，不分配内存。

默认的 `unique_ptr` 析构会沿链递归：销毁头节点时先销毁后继，再销毁后继的后继，深度为 n，长链表会栈溢出。`ListDeleter` 改为从前向后逐个释放：先摘下后继，再释放当前节点。测试用一百万个节点检查反转和销毁。
