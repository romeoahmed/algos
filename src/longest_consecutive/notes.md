# 最长连续序列

## 问题

给定未排序的整数序列，求数值连续的最长元素序列的长度：x, x + 1, …, x + k − 1 都出现时长度为 k。这些元素不必在原序列中相邻，重复值只算一次；空序列的答案为 0。要求期望 O(n) 时间。

对应 LeetCode 128。

## 思路

排序后线性扫描可以做到 Θ(n log n)。要达到线性，先把所有值放入哈希集合，“x 是否出现”就成了期望 O(1) 的查询。

朴素做法从每个值出发向上数，同一段会被反复数：段内每个值都会把它后面的部分再数一遍，一整段 1…n 需要 Θ(n²) 步。关键观察是**只从段的起点开始数**：x 是起点当且仅当 x − 1 不在集合中。每个值恰好属于一段，每段只从起点数一次，向上走的总步数等于不同值的个数。

哈希集合本身不维护顺序，却能在期望常数时间内回答“x − 1、x + 1 在不在”。排序提供的全局顺序在这里并不需要，相邻关系由这两种查询在局部重建出来。

## 伪代码

遵循[记号约定](../notation.md)。

```text
LONGEST-CONSECUTIVE(A)
    S ← A 中所有值构成的集合
    best ← 0
    for x in S
        if x − 1 ∉ S    // x 是一段的起点
            y ← x + 1
            while y ∈ S
                y ← y + 1
            best ← MAX(best, y − x)
    return best
```

## 示例

A = `[100, 4, 200, 1, 3, 2]`，S = {1, 2, 3, 4, 100, 200}：

| x   | x − 1 ∈ S | 动作           | 段长 |
| --- | --------- | -------------- | ---- |
| 1   | 否        | 走过 2、3、4   | 4    |
| 2   | 是        | 跳过           |      |
| 3   | 是        | 跳过           |      |
| 4   | 是        | 跳过           |      |
| 100 | 否        | 101 不在，停止 | 1    |
| 200 | 否        | 201 不在，停止 | 1    |

答案为 4，对应 1、2、3、4。集合的遍历顺序无关紧要，表中按数值排列只是为了便于阅读。

## 正确性

S 中的每个值 x 恰好属于一个极大段 [a, b]：a 到 b 的值全在 S 中，a − 1 与 b + 1 都不在。x 是起点当且仅当 x = a，因为 a 以外的段内值都有前驱 x − 1 ∈ S。从 a 向上走到第一个缺失的值 b + 1，得到该段的长度 b − a + 1。每个极大段恰好统计一次，最长连续序列就是最长的极大段，取最大值即为答案。

复杂度：外层循环对每个不同的值做一次 x − 1 的查询。内层循环只在起点处运行，走过的值恰好是该段的其余元素，各段互不相交，内层总步数不超过不同值的个数。加上每段末尾一次失败的查询，总查询次数为 O(n)。

测试把输入排序去重后线性扫描，统计相邻差为 1 的最长连续段，作为独立的参考方法。另用十万个连续整数检查运行时间：若漏掉起点判断，需要约 5 × 10⁹ 步。

## 复杂度与实现

建集合与扫描都是期望 Θ(n)，额外空间 Θ(n)；所有值都冲突时最坏 Θ(n²)。

Python 接受 `Iterable[int]`，`itertools.count(start)` 与 `itertools.takewhile` 从起点向上数出段长，再对所有起点取最大值。

C++ 把值转为 `std::int64_t` 放入 `std::unordered_set`，这样在 `int` 的两端计算 x − 1 与 y + 1 不会溢出：最小值没有 `int` 前驱、最大值没有 `int` 后继，在 64 位中都只是集合外的普通数。起点用 `std::views::filter` 筛选，段长用 `std::views::transform` 计算，最后用 `std::ranges::fold_left` 取最大值。返回 `std::size_t`。
